#{}：预编译占位符（安全）

原理：MyBatis会把#{}替换成?（JDBC的占位符），然后先编译SQL（数据库记住SQL结构），再传参数（参数会被当作“纯数据”，不会解析成SQL代码）。

例子：

```java
<select id="getUser" resultType="User">
    select * from user where username=#{username} and password=#{password}
</select>
```

实际执行的SQL（发给数据库）：

```plain
select * from user where username=? and password=?
```



参数（`username="admin"`, `password="123"`）会被**单独传**，数据库知道“这是数据，不是SQL代码”。







${}：字符串拼接占位符（不安全）

原理：MyBatis会直接把${}里的字符串拼接到SQL中，相当于“手动写死SQL”。如果参数是用户输入的，黑客可以构造恶意字符串，篡改SQL逻辑。











#{} 的底层原理（不是“编译文件”那么简单）

你理解的“先编译发给SQL，数据再通过另一个包发”方向是对的，但不够精确。

准确的过程是这样的：

你的代码：在 Mapper.xml 里写 insert into t_car values (#{k1}, #{k2})。

MyBatis 拦截：它发现你用了 #{}，于是它不发字符串拼接，而是把它翻译成 JDBC 的标准语法：insert into t_car values (?, ?)。

发送给数据库：MyBatis 把这个带 ? 的 SQL 发给数据库。

数据库预编译：数据库收到后，先进行预编译（Compile）。这时候数据库会检查 SQL 语法对不对，并且准备好执行计划。注意：这时候 ? 的位置是空的，数据库在等数据。

单独传数据：MyBatis 接着把 Map 里的数据（比如 "川A88888", "比亚迪"）单独打包发给数据库。

填入执行：数据库把收到的数据填进 ? 的位置，然后执行。

结论：#{} 的本质是 PreparedStatement，它是分两步走的（先送SQL骨架，再送数据），所以防注入。
