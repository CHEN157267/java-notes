Mybatis要求一定要写两个配置文件，写在main文件夹下的resources文件夹下



一个是核心配置文件，里面配置跟连接池相关的信息



一个是sql映射文件，把java对象映射成数据库中表的一条信息，也可以把数据库中一条记录映射成一个对象，在sql映射文件中编辑sql语句，最后需要使用sql语句的时候，在核心配置文件中写下mapper双标签，在双标签中写下mapper resource，在后面写下sql映射文件的路径就好了

id是sql语句的唯一标识，不可重复

在sql映射文件中，可以不以“；”为结尾







输入流，字节流是什么？



答：是一个**“管道”**，把硬盘上的文件内容“抽”到内存里给 Java 程序用。





这个输入流一定要指向Mybatis的核心配置文件



sql语句写在sql映射文件中的mapper双标签里



sql映射文件中的sql语句也有sqlid，在调用sql语句的时候需要用到sqlid，那这么说，sqlid是每一条sql语句都唯一的吗？还是说，同一个功能，比如说insert功能的id不能相同，但是总的其他功能加起可以有重复的id？



答：

**同一个 **`**namespace**`**（命名空间）下绝对不能有重复的 id**。真正调用的时候，MyBatis 是用 `**namespace + id**` 来定位 SQL 的。比如 `com.example.mapper.UserMapper.insert`和 `com.example.mapper.OrderMapper.insert`，它们是不同的。

Mybatis的底层使用了jdbc的事务管理器，这个管理器底层写了不提交，所以我们在使用mybatis的时候，需要手动提交





JDBC

就像是java和sql这两个语言的通用语言，跟json有点像。

| **概念** | **本质** | **跨语言？** | **类比** |
| :--- | :--- | :--- | :--- |
| **JSON** | 数据交换格式 | ✅ 任何语言都能解析 | 像**国际快递单**，不管寄到哪个国家，单子格式都一样 |
| **JDBC** | Java 访问数据库的 API 标准 | ❌ 只有 Java 用 | 像**中国的电源插座标准**，只有中国电器能插 |






**事务管理器（Transaction Manager）**：

+ **形象比喻**：它就像一个**“财务审批员”**。
+ **作用**：当你执行一连串操作（比如：转账扣款 100 -> 对方收款 100），必须保证这两步都成功，或者都失败。不能你扣了钱，对方却没收到。这个“要么全做，要么全不做”的规则，就是由事务管理器来强制执行的。
