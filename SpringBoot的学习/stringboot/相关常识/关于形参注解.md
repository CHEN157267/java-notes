**前端把数据放在哪儿，后端就用哪个注解去接。**

| | 数据位置 | 长什么样 | 用什么注解 |
| --- | --- | --- | --- |
| | URL 路径里 | `/user/delete/4` | `@PathVariable` |
| | URL 问号后面 | `/user/delete?id=4` | `@RequestParam` |
| | 请求体里 | `{"id":4}` | `@RequestBody` |




### 1. `@PathVariable`：数据在 URL 路径里，这里 `4` 是路径的一部分。
```java
DELETE /user/delete/4
```

后端怎么写：

```java
@DeleteMapping("/delete/{id}")
public String delete(@PathVariable Long id) {
    return "删除用户：" + id;
}
```

Spring 看到：

+ `/delete/{id}` 里的 `{id}` 是占位符
+ 实际请求是 `/delete/4`
+ 所以把 `4` 抠出来，赋给 `@PathVariable Long id`

所以方法里的 `id` 就是 `4`。``



### 2. `@RequestParam`：数据在 URL 问号后面
```java
DELETE /user/delete?id=4
```

这里 `id=4` 在 `?` 后面，叫查询参数。

后端

```java
@DeleteMapping("/delete")
public String delete(@RequestParam Long id) {
    return "删除用户：" + id;
}
```

Spring 看到：

+ URL 路径是 `/delete`
+ 问号后面有 `id=4`
+ 方法参数写了 `@RequestParam Long id`
+ 就把 `4` 赋给 `id`



### 3. `@RequestBody`：数据在请求体里
请求：

```java
DELETE /user/delete
Content-Type: application/json

{
  "id": 4
}
```

注意：`{"id":4}` 不在 URL 里，它在 **HTTP 请求体 body** 里。

后端怎么写：

```java
@DeleteMapping("/delete")
public String delete(@RequestBody DeleteUserRequest request) {
    return "删除用户：" + request.getId();
}
```

Spring 看到：

+ 方法参数有 `@RequestBody`
+ 请求体里是 JSON，其中，**前端必须在请求头声明 **`**Content-Type: application/json**`，否则 Spring 不知道这是 JSON，直接报 `415`。
+ 就用 Jackson 把 JSON 转成 Java 对象
+ 然后传给你的方法



**注意**：**不能同时写两个完全一样的 **`**@DeleteMapping("/delete")**`**，会冲突。**

## 五、实际开发中怎么选？
虽然 DELETE 也能带请求体，但实际开发不推荐。一般这么用：

| 场景 | 常用注解 | 例子 |
| --- | --- | --- |
| 根据 id 查详情 | `@PathVariable` | `GET /users/4` |
| 分页查询 | `@RequestParam` | `GET /users?page=1&size=10` |
| 新增用户 | `@RequestBody` | `POST /users`<br/> + JSON |
| 修改用户 | `@PathVariable`<br/> + `@RequestBody` | `PUT /users/4`<br/> + JSON |
| 删除用户 | `@PathVariable` | `DELETE /users/4` |
