它是**写给模型看的**，不是写给人看的注释。

### 7.1 三要素
| 要素 | 例 |
| --- | --- |
| 干什么 | "根据用户 ID 查询单个用户，返回 id、用户名和创建时间" |
| 什么时候用 | "当用户问'id 为 X 的用户''第 X 号'时使用" |
| 边界在哪 | "查不到时返回空。不返回密码" |


### 7.2 ⚠️ 不要把"写作说明"抄进去
错误示范（真实发生过）：

```plain
@Tool(description = "...当用户问 X 时用这个"，并且注明"如果查不到会返回空"...")
//                              ↑ 这是写给你自己看的指令
```

模型读到会想"我要注明什么？"

**判断标准一句话**：description 里**只应该有"对模型说的话"**，不该出现"并且注明""记得写""这里要说明"这类**指导你写作的元话语**。

**检验方法**：把它念出来，像不像在跟模型介绍这道菜？不像就是没转过来。

### 7.3 description 写清楚的收益（实测）
+ 写"查不到时返回空" → 查 id=999 时模型回答「结果为空，说明该用户不存在」，**没有瞎编**
+ 不写这句 → 它可能说"查询出错"，或者**编一个假用户**
