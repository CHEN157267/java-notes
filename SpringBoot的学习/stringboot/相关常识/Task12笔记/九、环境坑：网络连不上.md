### 9.1 症状
| 谁 | 结果 |
| --- | --- |
| `curl https://api.deepseek.com` | ✅ 通（401，说明网络正常） |
| Java 程序 `/ai/chat` | ❌ `ConnectException` / `ClosedChannelException` |


### 9.2 两个原因叠在一起
| 原因 | 表现 | 解法 |
| --- | --- | --- |
| **IPv6 优先** | Java 先试 IPv6，你的网络这条路径不通，**回退慢** | `-Djava.net.preferIPv4Stack=true` |
| **系统代理** | Clash 开着"系统代理"时，Java 把请求丢给 127.0.0.1:7897，节点不通 | `-Djava.net.useSystemProxies=false` |


**为什么 curl 没事**：它有快速回退（IPv6 一失败立刻换 IPv4），几乎感觉不到。Java 默认没这么积极。

### 9.3 配置位置
**IDEA**：Run → Edit Configurations → **Modify options** → **Add VM options**，填：

```plain
-Djava.net.useSystemProxies=false -Djava.net.preferIPv4Stack=true
```

**不能写进 **`**application.properties**`：

| 放哪 | 谁读 | 管什么 |
| --- | --- | --- |
| **VM options** | **JVM 启动时** | 网络栈、内存、编码 |
| `application.properties` | Spring 启动后 | 数据源、Redis、AI 配置 |


JVM 先启动，Spring 后读配置。网络栈行为必须在 JVM 启动那一刻就定。

### 9.4 判据（以后遇到同类问题）
"curl 能通、Java 不能" → 第一个怀疑 IPv6，第二个怀疑系统代理。
