## 二、Q1：模型不是“权限小”，是“**没有手**”
你的“管理员权限 vs 只能看到指定的方法”这个类比，把问题说成**视野**了。

真实的差别不在“能看到多少”，在“**能不能动手**”：

| | **模型** | **我们的代码** |
| --- | :--- | :--- |
| 知道该做什么 | ✅ 它判断 | —— |
| 能不能执行 | ❌ **没有执行通道** | ✅ 唯一能 new、能调 mapper 的地方 |


就算你把全部方法都注册给它，它**还是只能输出一段 JSON**。不是“权限不够”，是**它从头到尾没有能执行代码的入口**。

一句话改法：**“模型有判断力，没有执行能力”** —— 这比“权限”准确得多。

## 三、Q3：缺的那个词是“**抽取**”
你说的“这个 4 是用户请求发来的” —— 对，但**用户原话里没有“id=4”这个字段**，只有一句中文：

plaintext

```plain
"帮我查一下 id 为 4 的用户"
```

模型做的是：**从自然语言里抽出**** **`**4**`**，并且判断出它应该填进**** **`**id**`** ****这个参数**。

这个动作叫**参数抽取**（或“槽位填充”）。它是模型最核心的能力之一 —— 也正是它容易出错的地方（你以后会遇到“它把年份当 id”这种事）。

## 四、Q5：你漏的那条最硬 —— **没有人工确认**
你说的三条我都认（会改数据 / 会影响类的纯粹度 / 爆炸半径大）。但最根本的一条你没说：

**写操作一旦执行，没有“确认”这一环，也不可撤销。**

查错了，最坏是答非所问；**删错了，数据就没了。** 而且参数是模型填的 —— 它可能把“删除 id 为 4 的用户”理解成 `id=40`，你连拦的机会都没有。

业界的做法不是“相信模型”，是**把写操作挡在工具之外**，或者加**人工确认**（“即将删除用户 zhangsan，确认吗？”）。这就是你说的“爆炸半径”的真正含义 —— **能爆炸的动作，别放进模型够得着的地方。**

## 五、Q6：例子你得自己说出来
你写“例子就是我们代码那个 description”——**这句话本身不算回答**，它说明你知道位置，但没说清**错在哪**。

那个 description 里混进去的是：

```plain
……“当用户问 X 时用这个”，并且注明“如果查不到会返回空”
                    ↑ 这三个字是写给你看的指令，不是给模型看的描述
```

**判断标准一句话**：description 里应该**只有“对模型说的话”**，不该出现“并且注明”“记得写”“这里要说明”这类**指导你写作的元话语**。
