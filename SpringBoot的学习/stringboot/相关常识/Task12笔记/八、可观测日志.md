### 8.1 格式
```plain
[工具] 名称 参数 -> 结果 耗时
```

实测输出：

```plain
[工具] getUserById id = 999 -> 未找到  耗时 6 ms
[工具] getUser 返回 10 条，耗时 35 ms
[工具] getUserById id = 4   -> 找到 zhangsan 耗时 3 ms
```

### 8.2 三个必须有的字段
| 字段 | 缺了会怎样 |
| --- | --- |
| **工具名** | 工具多了以后日志全长一样，分不清是谁打的 |
| **参数** | 出问题无法复现"它到底传了什么" |
| **结果状态** | 查不到时看不出来，会以为查询成功了 |


### 8.3 用 `{}` 占位符，别用 `+`
```plain
log.info("[工具] getUser 返回 {} 条，耗时 {} ms", users.size(), cost);   // ✅
log.info("[工具] getUser 返回 " + users.size() + " 条");                  // ⚠️
```

`{}`**所有级别都能用**（不是 error/warn 的特权）。差别在于：级别不够时，`+` 拼的字符串**已经算完了才被丢弃**。

### 8.4 一个更根本的问题（留待以后）
10 个工具就要写 10 遍"计时 → 调用 → 打日志"。加了第 11 个还可能忘。

标准解法是 **Advisor**（拦截器）：在流程上挂一个钩子，所有请求/工具调用都过一遍，统一处理。

重复的横切逻辑，通常有统一的挂载点。 这是读框架源码时反复出现的思路（AOP 思想）。
