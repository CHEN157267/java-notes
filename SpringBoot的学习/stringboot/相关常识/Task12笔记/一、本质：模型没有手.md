这是整个 Task 的核心，一句话：

**模型有判断力，没有执行能力。**

| | 模型 | 我们的代码 |
| --- | --- | --- |
| 判断"该做什么" | ✅ | —— |
| 执行 | ❌ **没有执行通道** | ✅ 唯一能调 mapper 的地方 |


它做的事只有一件：**输出一段描述"我想调什么"的 JSON**。

```plain
ToolCall[
  id   = call_00_Ahzp355x7gl3z4Szwu6E6785,
  type = function,
  function = ChatCompletionFunction[
      name      = getUserById,
      arguments = {"id": 4}
  ]
]
```

**到这里就结束了。** 后面全靠 `ToolCallingManager` 用反射去调你的方法。

### 完整链路
```plain
我们发请求（带工具清单）
   ├─ messages = [ 用户那句话 ]
   └─ tools    = [ getUser, getUserById ]     ← 菜单是我们写的
        ↓
模型返回「要调 getUserById，id=4」
        ↓
ToolCallingManager 反射调用 userTools.getUserById(4)   ★ 真执行在这
        ↓
结果拼成一条 TOOL 消息，连同前面所有 messages 再发一次
        ↓
模型生成最终回答 → 返回给前端
```

常见误解：以为"模型权限小，只看到部分方法"。 不是权限问题 —— 就算把全部方法都给它，它还是只能输出 JSON。
