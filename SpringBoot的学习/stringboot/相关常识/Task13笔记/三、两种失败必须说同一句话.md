### 3.1 问题
```plain
if (user == null) throw new BusinessException("用户不存在", 404);
if (!matches(...)) throw new BusinessException("密码错误", 401);
```

**这是在免费给攻击者送信息**：

| 他输入 | 看到 | 得到什么 |
| --- | --- | --- |
| 真实用户名 | “密码错误” | **这个用户名存在** |
| 乱打的 | “用户不存在” | 换个再试 |


**手法名字：用户名枚举（User Enumeration）** —— 通过错误提示的差异，批量判断哪些用户名真实存在。

**收益对比**：从“试一百万次碰运气”变成“拿到真实名单后集中爆破”，效率提高几十倍。

### 3.2 正确做法
```plain
if (user == null || !encoder.matches(password, user.getPassword())) {
    log.warn("登录失败: username={}", username);      // 只记名字
    throw new BusinessException("用户名或密码错误", 401);
}
```

**两个注意点**：

1. `user == null`**必须写在 **`**||**`** 前面** —— 靠短路求值躲开空指针
2. 状态码统一用 **401**（认证失败），不用 404（那又多泄露一层“这是个资源问题”）

### 3.3 这里有一个反直觉的对立
| 去处 | 该说什么 |
| --- | --- |
| **日志** | 真实原因（用户不存在 / 密码不匹配）—— 排查要用 |
| **响应** | 统一一句模糊话 |


**跟 Task6 那条“报错要详细”不矛盾** —— 那条说的是日志，这条说的是响应。
