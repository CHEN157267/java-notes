### 7.1 DTO：`RagHit`
```plain
source      来自哪个文件
score       相似度
chunkIndex  本文第几块（用于看召回是否连续）
preview     前 50 字（给人看）
@JsonIgnore
content     完整正文（给模型看）
```

**为什么要有 DTO，不直接返 **`**Document**`：

| 理由 | 说明 |
| --- | --- |
| **不暴露框架对象** | `Document` 带 id、metadata、内部字段 |
| **解耦** | 换掉 Spring AI，接口一行不用改 |
| **两种用途分离** | `/rag/search` 给人看（preview）、`ask` 给模型看（content） |


`**@JsonIgnore**`** 的作用**：序列化成 JSON 时跳过这个字段 → 前端看不到 `content`，但 Java 代码里读得到。

### 7.2 ★ 一个血泪教训：`preview` 不能喂模型
最初 `ask()` 复用了 `search()` 返回的 `RagHit`，只拼了 `preview`：

```plain
块平均 554 字，preview 只有 50 字符 → 覆盖率 9%
更糟：这 50 字符里 ASCII 占 67%~94%（路径、表格符、代码）
      例：src/main/resources/application.properties Key 占位、 → 49 字符里 46 个 ASCII
      → 中文信息只剩 2~12 个字
```

**结果**：模型只看到 9% 的内容，答案自然离谱。

**所以 **`**content**`** 这个字段不是为了好看，是必需的。**

### 7.3 拼装格式
```plain
【资料1】来源：学习笔记-Task8-业务异常重构.md
（正文）

【资料2】……

【问题】重试为什么要有最大间隔
```

**为什么要带来源**：答案错了，要能分辨是"**检索错了**"还是"**模型理解错了**"。

### 7.4 system 提示词（三句就够）
```plain
你是一名知识库问答助手。只根据【资料】回答，不要用你自己的知识补充。
资料里没有的信息，直接回答「笔记里没有相关内容」。
资料之间如有冲突，以更具体的那条为准。
```

**不要写"至少保留 1 条资料"这种话** —— 它跟"没资料就说不知道"直接矛盾，会逼模型硬编。

### 7.5 ⚠️ "没找到"不是异常
```plain
if (ragHits.isEmpty()) {
    return "笔记里没有相关内容";     // ✅ 正常返回 200
}
```

**判据**：这是"**程序执行不下去了**"，还是"**业务上的正常分支**"？

| 情况 | 是异常吗 |
| --- | --- |
| 笔记里没相关内容 | ❌ **不是**（跟"搜索返回空列表"一样） |
| `q` 为空 / `topK <= 0` | ✅ 业务异常 400 |
| 向量库空了 / Key 失效 | ✅ 系统异常 503 |


**如果抛 **`**RuntimeException**`，兜底 handler 会返回 `code=500 系统繁忙`，还打 ERROR 日志 —— **语义完全错，而且告警疲劳**。
