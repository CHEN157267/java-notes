### ★ Q4.1：值传递 **+** 变量遮蔽，两个都要
只答"值传递"**不够**。看这两行：

```plain
private int seq;                                  // 字段
private void addChunk(..., int seq) { seq++; }    // 形参，同名 → 遮蔽字段
```

**变量遮蔽（shadowing）**：方法内部出现同名局部变量/形参时，**它会把字段"挡住"**，方法里的 `seq` 指的是**形参**。

于是：

| 谁在动 | 结果 |
| --- | --- |
| `run()` 里 `seq = 0` | 字段 = 0（没问题） |
| `addChunk()` 里 `seq++` | **形参副本** +1，字段不动 |
| 每次调用 `addChunk` | 传进去的都是字段值 **0** |


**两个机制缺一不可**：

+ **遮蔽**决定了"方法里那个 `seq` 不是字段"
+ **值传递**决定了"改了也传不回去"

**如果只是值传递、但写 **`**this.seq++**`，就完全没问题 —— 所以遮蔽才是主犯。

**修法三种**：① 删形参 ② 写 `this.seq++` ③ 把 seq 做成方法返回值

### ★ Q8.3：单例跟这件事的关系
**关键是"同一个对象"**：

```plain
RagConfig 造出 vectorStore（一个对象）→ 登记进容器
        ↓ 容器把这个【引用】发给两处
RagLoader    → 拿到引用 A ─┐
RagServiceImpl → 拿到引用 B ─┴→ A、B 指向同一个对象
        ↓
RagLoader 调 add() 往里面塞数据
        ↓
ServiceImpl 之后 search() 时，看到的就是塞满的那份
```

**如果每次注入都新建一个**，Loader 塞的那份和 Service 查的那份就是**两个空盒子** —— 检索永远查不到东西。

**这就是"单例"在这件事里的作用：不是省内存，是保证"我塞的东西你看得见"。**

顺带：`vectorStore` 构造时是空的 ≠ 有 bug。**空 Map 是合法状态**，对象本身是完整的。这跟 `@Autowired` 字段注入的"壳"（依赖为 null，一调就 NPE）不是一回事。

### ★ Q9.1：`@Bean` 和 `@Component` 的本质分别
| | `@Component` | `@Bean` |
| --- | --- | --- |
| 标在哪 | **类** | **方法** |
| 谁负责 `new` | **Spring**（反射调构造器） | **你写的这个方法** |
| 适用于 | **你自己写的类** | **别人的类 / 需要复杂构造的类** |
| 一句话 | **我自己报名** | **我替你报名** |


**为什么 **`**SimpleVectorStore**`** 必须 **`**@Bean**`（三个理由叠加）：

1. 它是 **Spring AI 的类**，你**不能**在别人 jar 的代码上加 `@Component`
2. 它的**构造器是 **`**protected**`，Spring 没法直接 `new`
3. 它需要 `EmbeddingModel` 才能造 → 只能你写方法说清"用什么参数造"

`@Bean` 的本质就是：**"配方"由你写，成品登记给容器。**

### Q2：两个括号
| 符号 | 作用 | 去掉会怎样 |
| --- | --- | --- |
| `(?m)` | 多行模式：让 `^``$` 认**每一行**的首尾（默认只认整个字符串的首尾） | 只在开头切一刀 → 几乎切不动 |
| `(?=...)` | **零宽正向断言**：断言"这个位置后面是 `## `"，但**不消耗字符** | 改成 `^## ` → `## ` 被当分隔符**吃掉**，标题没了 |


`**split**`** 的固定行为：丢弃分隔符**。所以：

```plain
"## 五、密钥管理\n...".split("## ")  →  ["", "五、密钥管理\n..."]   // [0] 是空串
sec.lines()                          ≡  sec.split("\n")            // 保留 "## "
```

## 五、顺带补一个 Java 知识点：多态里谁优先
| 成员 | 看谁 | 结果 |
| --- | --- | --- |
| **方法** | 运行时看**实际对象类型** → **子类优先** | 动态绑定（虚方法表） |
| **字段** | 编译期看**引用类型**（声明的是谁）→ **父类优先** | 静态绑定 |


```plain
class A { String name = "A"; void hi(){ print("A"); } }
class B extends A { String name = "B"; void hi(){ print("B"); } }

A a = new B();
a.name   → "A"    // 字段看左边
a.hi()   → "B"    // 方法看右边
```

**口诀：方法看右边，字段看左边。**

（字段不叫"覆盖"，叫**隐藏** —— 父类那个字段还在，只是你通过父类引用看不到子类那个。）

## 六、贴显示器上的六条
1. **chunk 是检索的最小单位** —— 切碎了，再好的模型也答不出。
2. `**split**`** 丢分隔符；**`**(?=)**`** 不消耗字符** —— 一个吃、一个不吃。
3. **方法形参一旦同名，就会遮住字段** —— 想改字段就写 `this.xxx`。
4. **别依赖别人顺手给的元数据** —— 换实现就没了，还是 NPE 这种最难懂的形式。
5. **筛选分三层**：检索器阈值（0.0）→ topK（5）→ 业务阈值（0.5）。
6. **先造对象、再灌数据、最后才查** —— 单例保证"你塞的我看得见"。
