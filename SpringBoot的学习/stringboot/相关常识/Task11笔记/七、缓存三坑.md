| | 问题 | 触发条件 | 解法 |
| --- | --- | --- | --- |
| **穿透** | 查**库里根本不存在**的数据，缓存永远拦不住，每次打库 | 数据本身不存在（含恶意随机 id） | 缓存空值（短 TTL）/ 布隆过滤器 / **接口层限流·校验** |
| **击穿** | **单个热点 key** 过期那一瞬，并发请求同时回源 | 一个热点 key 过期 | 互斥锁（`SET NX`）/ 永不过期 + 后台更新 |
| **雪崩** | **大批 key 同时过期**，请求集中打库 | 同刻过期（如一起设 30 分钟） | 过期时间 + 随机偏移 |


### 7.1 穿透为什么"根治在接口层"
"缓存空值"只能挡**同一个** key 反复查；攻击者每次换随机 id，就会往 Redis 塞海量空标记 → **把缓存撑爆**。

+ **布隆过滤器**：能判断"这个 key **一定不存在**"，直接拦掉，适合随机 key；
+ 但它只挡"不存在"的，且不能删元素；
+ 只要请求合法、数据真的不存在，**总有一次要问数据库** → 真正根治在**接口层**：参数校验、限流、鉴权。

### 7.2 互斥锁的实现（`SETNX`）
```plain
SET lock:user:list 1 NX EX 10   ← 只在 key 不存在时设置成功 = 抢到锁
```

+ `NX` = Not eXists，抢锁成功/失败一目了然；
+ `EX 10` 是**锁的租约**（上限 10 秒），**不是"等待 10 秒"、也不是"给代码的执行时间"** —— 它是兜底：防止持锁的进程崩了，锁永远不释放把整个接口焊死；
+ 抢到锁的去查库 + 重建缓存，**干完主动 **`**DEL**`** 释放**，别等它自然过期；
+ 没抢到的：睡 50ms 后重试读缓存，或直接返回旧值。

这里不需要写线程代码 —— Tomcat 每个请求一个线程，同一个方法被 200 个线程同时执行而已。`sleep` 是"退避重试"。
