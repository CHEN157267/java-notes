## 二、错题详解（重点看这五处）
### ★ Q10.2 反序列化的方向搞反了
你写："`readValue` 是将 String 转化成 JSON" —— **反了**。

| 方法 | 方向 | 叫什么 |
| --- | --- | --- |
| `writeValueAsString(对象)` | 对象 → JSON 字符串 | **序列化** |
| `readValue(字符串, 类型)` | JSON 字符串 → 对象 | **反序列化** |


记忆钩子：`**read**`** 是"读回来"，读回来当然是读成对象**；`write` 是"写出去"，写出去才变成字符串。

那么 `TypeReference` 是干嘛的？—— Java 泛型在编译后会被**擦除**，`List.class` 只剩下"我是个 List"，**元素类型 **`**User**`** 丢了**。Jackson 拿到 `List.class` 只能给你 `List<LinkedHashMap>`，每个元素是 Map 而不是 User，你后面 `user.getUsername()` 就崩。

```plain
// ❌ 编译过得去，运行时得到 List<LinkedHashMap>
objectMapper.readValue(json, List.class);

// ✅ 匿名子类把泛型信息"刻"在字节码里，Jackson 靠反射读得到
objectMapper.readValue(json, new TypeReference<List<User>>() {});
```

一句话：`**TypeReference**`** 是给泛型"留证"的**。

### ★ Q12 又栽在同一个说法上：`data` 不是"装 jar 的"
你的答案（`spring.data.redis.host` 有效、写错不生效）**全对**，但理由还是那句"Spring Boot 3 整了个 data 来装这些跟数据操作有关的 jar 包" —— 这句话把两个东西混成一个了：

| | 归谁管 | 长什么样 |
| --- | --- | --- |
| **jar 从哪来** | `spring-boot-starter-data-redis`（pom） | 依赖 |
| **配置项叫啥** | `spring.data.redis.*`（properties） | 属性名 |


`data` 在这两处**只是名字撞了**：

+ 依赖里的 `data` = "数据访问家族"（data-redis / data-jpa / data-mongo）
+ 配置里的 `spring.data.` = "数据访问类配置的统一前缀"

**Boot 3 干的事只是搬配置前缀**（`spring.redis.*` → `spring.data.redis.*`），它没动依赖。写错前缀的后果是**静默失效**：不报错、不提示，你以为配了其实没配。

### ★ Q7 互斥锁的命令：`SETNX`
你流程答得对，就差那个命令。三个名字记住一个：

| 命令 | 含义 |
| --- | --- |
| `SET key value NX` | 只在 key **不存在**时设置成功（NX = Not eXists），这就是"抢锁" |
| `SET key value NX EX 10` | 抢锁 + 10 秒自动释放（防止持锁的进程挂了把锁焊死） |
| `DEL key` | 用完释放 |


伪代码（看懂就行，不用背）：

```plain
if (SET lock:user:list 1 NX EX 10 成功) {
    try   { 查库 → 写缓存 }
    finally { DEL lock }                       // 一定要释放
} else {
    睡 50ms 后重试读缓存，或直接返回旧值
}
```

**为什么必须"睡一下再读"**：另一个线程正在查库重建，你立刻读还是读不到，会白打一次库。

### ★ Q8.1 add 为什么要删缓存：你的表述乱了
你写"添加后的数据不一定要被使用到" —— 这句是多余且不成立的，判卷时反而扣了印象分。真正的理由只有一条，而且很硬：

缓存里存的是**整张表的快照**（`user:list`）。新增一个人，**这个快照就过期了** —— 它少了一条。用户刷新看到的还是"没有新人"的旧列表。

所以：**只要"被缓存的那份数据"变了，就必须删 —— 不管变的是新增、修改还是删除。**

### ★ Q3 小偏差：过期滞留 ≠ 击穿
你答"过期了可能没被及时删除，而且可能会出现击穿情况" —— 前半对，后半是**硬拉因果**。

+ 过期 key **滞留**：只是占内存、读不到，不影响性能；
+ **击穿**：热点 key 过期那一刻，**并发**请求同时回源。

两者的共同点只有"都涉及过期"，但滞留不会"导致"并发。**别为了多写一句把两件事缝在一起** —— 这在考试里是加分项，在工程里会误导排查方向。

## 三、半对题的补强
### Q1 Redis vs 本地 Map：你漏了最关键的一条
你写了"容量大、多机共享、持久化" —— 都对。漏掉的是：

**Redis 是独立进程，缓存不占 JVM 的堆。**

`Map` 存在 JVM 堆里，缓存几十万条对象 → 堆涨 → GC 频繁 → 严重时 OOM 把服务弄死。Redis 在外面的进程里，**它的内存压力和你的服务是隔离的**。

补全后是四条：**多进程共享 / 不占 JVM 堆 / 过期与淘汰由中间件管 / 可选持久化**。（"更快"依然不算理由。）

### Q2 结论对，但要能说出"为什么不同"
你说"跟环境变量没关系" ✅。考官想听的是**本质差异**：

| | 环境变量 | Redis 的 key/value |
| --- | --- | --- |
| 谁持有 | 操作系统，随进程继承 | Redis 服务进程 |
| 谁能读 | 该进程及其子进程 | **所有连上来的客户端** |
| 谁命名 | 建变量的人 | 你的代码 |
| 生命周期 | 跟随系统/会话 | TTL 或永久 |

"parent 管" ✅。但"会直接报错"要说得更准：**Maven 强制要求 **`**version**`**，缺失时构建直接失败**（报 `'dependencies.dependency.version' is missing`）。这不是警告，是**构建不了**。

## 四、Q13 那道思考题：你的直觉是对的，问题在"怪"的地方
你判断"Redis 挂了还能用，因为 catch 里回退查库" ✅ 路径完全正确 —— 这叫 **fail-open（失败开放）**：辅助组件挂了，主流程继续。

你觉得"怪"的地方，其实是两个真问题：

1. **每次请求都要等 Redis 超时**。Redis 挂了不是"立刻报错"，而是**连接超时后才报错**（默认可能几秒）。这段时间每个请求都被卡住 → 服务像假死。 → 解法：把 Redis 的**超时设短**（几百毫秒），并加**熔断**（连续失败 N 次后，一段时间内直接跳过 Redis，不再尝试）。
2. **catch 里的降级没有日志级别区分**。现在打 `warn` 是对的（可恢复），但如果每分钟几百条 warn，说明该报警了。

所以这个设计**方向对、缺两道保险**：短超时 + 熔断。

## 五、一张表收口（考试/面试都能直接用）
| 概念 | 一句话 |
| --- | --- |
| Redis 是什么 | 独立进程里的 `Map<String, byte[]>`，跨进程共享 |
| 缓存三坑 | 穿透（查不存在的）、击穿（单个热点 Key 过期）、雪崩（大批同时过期） |
| 对应解法 | 空值/布隆、互斥锁/永不过期、过期时间加随机 |
| 过期删除 | 惰性删除 + 定期随机抽 20 个（比例 >25% 再抽），**不保证准时** |
| 命中率 | 命中次数 ÷ 总请求次数 |
| 序列化 | `writeValueAsString` 出、`readValue` 回；泛型靠 `TypeReference` 留证 |
| 依赖 vs 配置 | starter 管 jar，`spring.data.redis.*` 管属性名，两回事 |
| 失效时机 | 数据一变就删 key，**不是等它自己过期** |
| 降级 | fail-open + 短超时 + 熔断 |
