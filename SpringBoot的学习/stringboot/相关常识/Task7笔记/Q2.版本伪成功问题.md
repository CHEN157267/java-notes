**报错关键字**：`NoSuchMethodError`（"找不到方法"）+ 版本太老。

| 事实 | 说明 |
| --- | --- |
| Knife4j 4.5.0（2024-01 后没再发版）自带 springdoc **2.3.0** | 老 |
| 你的项目 Spring Boot 3.5.16（Spring 6.2） | 新 |
| Spring 6.2 **删了**`ControllerAdviceBean` 的单参构造器 | → 老 springdoc 调不到 → `NoSuchMethodError` |


**修法（pom 动两处）**：`<exclusions>` 排掉老 springdoc → 显式换 `springdoc-openapi-starter-webmvc-ui:2.8.15`。

**"伪成功"的本质**：应用能启动、页面能开，但 `/v3/api-docs` 只有 67 字节、接口全无。判断依赖通不通，**只看功能输出，不看进程活着**。



| 判定 | |
| --- | --- |
| ① 产生了 error | ✅ springdoc 调了一个被删的构造器 → 抛 `NoSuchMethodError`<br/>（Error） |
| ② advice 接不了，属于不同类的东西 | ✅ 准确说是类型匹配不上：我们的 handler 声明接 `Exception`<br/>，而它是 `Error`<br/>，不是 Exception 的子类 |
| ③ 后来甩给了 spring 底层 | ✅ 意思对，换个词——不是"甩"，是一路往外抛（冒泡），谁都没接，最后落到 Spring MVC 的核心 `DispatcherServlet` |
| ④ 被 servlet 包装成 exception 类型的异常 | ✅ `ServletException`<br/>（`DispatcherServlet`<br/> 里写死了 `catch (Throwable err)`<br/>，包一层再往外递） |
| ⑤ 由我们写的 500 兜底方法接住 | ✅ 就是 `handleException(Exception e)` |


补一个"伪"的关键：我们的 handler 没写 `@ResponseStatus`，所以那次的 HTTP 状态码很可能还是 200，只是响应体里的 `**code**` 是 500 —— 所以从外面看"一切正常"。

⚠️ 但这一条我得说清楚：它是推断，不是实测。当年只记了"body 67 字节 + `doc.html` 200"，没记 `**/v3/api-docs**` 的状态码。
