### 枚举常量是什么
**"枚举"** = 建个类，**提前创建好几个对象**，要用哪个就调哪个。 **"枚举常量"就是这个"提前建好的对象"的正式称呼。**

```plain
JsonProperty.Access 里的 4 个常量对象：
  AUTO / READ_ONLY / WRITE_ONLY / READ_WRITE
```

`JsonProperty.Access.WRITE_ONLY` 读作："`**Access**`** 枚举里那个名叫 WRITE_ONLY 的常量对象**"。

| | C 的宏常量 `#define MAX 100` | Java 枚举常量 |
| --- | --- | --- |
| 本质 | 预处理期**文字替换** | **真正的对象**，**类加载时**创建 |
| 有类型吗 | 没有，就是一段文字 | 有，类型是 `Access` |
| 能调方法吗 | 不能 | 能 |


（Java 里跟宏常量最像的是 `static final int MAX = 100;`，叫**类常量**。）

**★ 类加载时创建** → 全局只有一份：

```plain
JsonProperty.Access.WRITE_ONLY == JsonProperty.Access.WRITE_ONLY   // 永远 true
```

**⚠️**** 大小写敏感，差一个字母就是两个符号：**

| 写法 | 是什么 |
| --- | --- |
| `access`（小写 a） | **属性名**，写在注解里 |
| `Access`（大写 A） | **枚举类型名**，`JsonProperty` 里的嵌套类型 |


### 两种写法为什么等价 —— 桥梁是 `import static`
```plain
import static com.fasterxml.jackson.annotation.JsonProperty.Access.WRITE_ONLY;
```

这行把 `WRITE_ONLY` 这个名字**直接搬进当前文件**，于是能省掉 `JsonProperty.Access.` 前缀。

```plain
@JsonProperty(access = WRITE_ONLY)                      // 配 static import
@JsonProperty(access = JsonProperty.Access.WRITE_ONLY)  // 全限定，不必 static import
```

**两种写法编译出的字节码完全一样。**

不过注意 —— 它们是**同一机制的不同层级**，不是"导包深浅"：

| 语句 | 导的是 | 之后能简写 |
| --- | --- | --- |
| `import java.util.List;` | 一个**类** | `List`（否则要 `java.util.List`） |
| `import static ...Math.PI;` | 一个**静态成员** | `PI`（否则要 `Math.PI`） |


`**import**`** 给类省前缀；**`**import static**`** 给静态成员（常量、静态方法）省前缀。同一个机制扩大到了成员级别。**

阿伟老师演示的"不导包要写很长的全限定名" —— 那是**类**的层面；`import static` 是**成员**的层面。

### 那 IDE 为什么标红/改代码？
因为你点过它能给的那个提示 —— **"导入 static 常量 WRITE_ONLY"**。IDEA 的意图操作一执行，就会把 `JsonProperty.Access.WRITE_ONLY`**替换成**`WRITE_ONLY` 并补上 static import 行。

**这是 IDE 的风格建议，不是报错。**

**★ 实测**：写个临时文件用全限定写法编译 → `javac exit=0`。**编译器说这写法没问题。** 本机 `.m2` 里 jackson-annotations 只有 **2.21 一个版本**，不存在"两个包打架"。
