相关概念：



哈希是什么

**核心思想**：把任意长度的东西，压成固定长度的一小段，且**同样输入永远得到同样输出**。



攻击者要的是**密码原文**，不是"打库"。篡改、勒索是**另一类**威胁（SQL 注入那条线），跟存不存明文不是一回事。

### 最狠的一刀：撞库（credential stuffing）
用户密码一旦泄露 → 他很可能在微信 / 支付宝 / 学校系统用**同一个密码** → 受害的是他在**别处**的账号。

撞库：黑客拿着泄露的用户的数据去试这些用户的其他软件的密码，攻击者是在拿一批账号密码去撞一批网站

## 加密 vs 哈希：一字之差，天壤之别
| | **加密** encrypt | **哈希** hash |
| --- | --- | --- |
| 可逆 | ✅ 有钥匙就能解回 | ❌ **永远不能** |
| 依赖 | **必须有钥匙** | 不需要钥匙 |
| 能不能存密码 | ❌ 不能用 | ✅ 用这个 |


### 为什么可逆加密不适合存密码
+ 登录是**程序自动**比对的 → 钥匙必须随时可用 → 只能躺在配置文件 / 环境变量 / 代码里
+ 攻击者拿到服务器或备份，钥匙就到手了
+ **等于把钥匙和保险箱放在同一个房间里**
+ **不是算法不行，是钥匙没地方藏**

一句记住：**不可逆 = 没有钥匙 = 没有东西可被偷。**

### **在线攻击 vs 离线攻击**
| | **在线（打登录接口）** | **离线（拿到密文后）** |
| --- | --- | --- |
| **算在哪** | **你的服务器** | **他自己的电脑上** |
| **拦得住吗** | ✅** 限流 / 5 次锁定 / 验证码** | ❌** ****拦不住，也感知不到** |
| **每次成本** | **网络往返 + 100ms** | **只剩他自己的 CPU** |


**攻击者破解的手段和用户登录的手段本质上是同一个。**** 区别只在"在哪算"。 ****BCrypt 的"慢"就是专门为右边这一列设计的**** —— 你那些在线防线对离线攻击一点用没有，人家压根没经过你的服务器。**

****

**BCrypt 不保证某个账号一定破不了。它做的是：****让"一次破解命中全库"变成"必须逐个账号穷举"，并把每次穷举的成本抬到不划算。它保护的是强密码，不是任何密码。**
