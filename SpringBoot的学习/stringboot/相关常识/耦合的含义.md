**<font style="color:rgba(0, 0, 0, 0.9);">耦合 = 两个东西绑在一起的紧密程度。</font>**

**<font style="color:rgba(0, 0, 0, 0.9);">手动 new = 强耦合</font>**<font style="color:rgba(0, 0, 0, 0.9);">：调用方</font>**<font style="color:rgba(0, 0, 0, 0.9);">直接认识具体实现类</font>**<font style="color:rgba(0, 0, 0, 0.9);">，被焊死：</font>

```java
private UserServiceImpl svc = new UserServiceImpl(new UserMapperImpl());
// ① UserServiceImpl 构造函数一改 → 这行就得改
// ② 想换成带缓存/事务的版本 → 这行必须改
// ③ 最要命：UserMapperImpl 这个类根本不存在，你 new 不出来（MyBatis 才有）

```

**<font style="color:rgba(0, 0, 0, 0.9);">注入 = 松耦合</font>**<font style="color:rgba(0, 0, 0, 0.9);">：调用方</font>**<font style="color:rgba(0, 0, 0, 0.9);">只认接口</font>**<font style="color:rgba(0, 0, 0, 0.9);">，不知道背后是谁：</font>

```java
@Autowired private UserService userService;   // 换实现？这行不用动

```



<font style="color:rgba(0, 0, 0, 0.9);">"强耦合"的危害具体是：兼容复用性差，</font>**<font style="color:rgba(0, 0, 0, 0.9);">实现一变，调用方被迫跟着变；而且调用方被迫知道了一堆它本不该关心的实现细节。</font>**
