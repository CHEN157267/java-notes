### 1.1 BOM 解决了什么
**你的答案**：依赖多、版本容易冲突；BOM 是别人写好的版本，省去一个个试。

**✅**** 这层是对的。** 补两点：

**① BOM 的核心价值是"一套版本互相兼容"**，不是"省事"。Spring AI 拆成十几个模块（starter / model / client-chat / commons…），**版本必须完全一致**，否则会出现"能编译、跑起来 NoSuchMethodError"（这就是 Task7 那个坑）。

**② 你说的 **`**import**`** scope（你问"scope 是干啥的"）**：

```plain
<dependency>
    <artifactId>spring-ai-bom</artifactId>
    <type>pom</type>        
    <scope>import</scope>   
</dependency>
```

+ `scope=import`**只能配合 **`**type=pom**`** 用**，而且只在一个地方合法：`<dependencyManagement>` 里
+ 它的意思是"**不要把这份 pom 当依赖引入，只把它的版本规定抄过来**"
+ 一句话：**它是"抄规则"，不是"拿东西"**

### 1.2 starter 为什么不写 version
**你的答案**：因为 dependencyManagement 里写了。

**✅**** 完全正确。**

### 1.3 变量该放哪
**你的答案**：放在 `<properties>` 里，引用是 `{$…}`。

**方向对，符号写反了**：是 `**${…}**`（美元在前，花括号包住名字），不是 `{$…}`。

+ 定义：`<spring-ai.version>1.1.8</spring-ai.version>`（在 `<properties>` 里）
+ 引用：`<version>${spring-ai.version}</version>`

## Q2 配置与优先级
### 2.1 ⚠️ 这题是本轮最值钱的坑
**你的答案**：不能启动会炸，会抛异常，Spring AI 会抛 `NonTransientAiException`。

**❌**** 前半错了，后半对了。** 分两种情况（都实测过）：

| 情况 | 结果 |
| --- | --- |
| properties 里**完全没写**`spring.ai.deepseek.api-key` | **启动直接失败**：`DeepSeek API key must be set` |
| properties 里**写了**`${DEEPSEEK_API_KEY}`，但**环境变量缺失** | **能启动** ✅ 故障延后到调用时才炸 |


**为什么"能启动"？** 因为环境变量没解析出来时，Spring 把**字面量 **`**${DEEPSEEK_API_KEY}**`** 原样当成了 key** —— 它是个**非空字符串**，所以启动校验（`Assert.hasText`）通过了。

**所以真实表现是**：启动没有任何报错 → 一调接口 → 401 → `NonTransientAiException`。

**记住这句话**：

**"配了引用但值没来" → 能启动、调用才炸（最阴险）；"压根没配" → 启动就炸（反而好查）。**

### 2.2 优先级
**你的答案**：命令行参数 > 环境变量 > application.properties > 框架默认值

**✅**** 完全正确。**

### 2.3 为什么必须加 `--server.port=8080`
**你的答案**：不加会有"什么什么"来捣乱（忘了），但命令行优先级最高能压住。

**方向对，那个"捣乱的"是什么要记住**：

## Q3 ChatClient 方法链
### 3.1 四步的类型
**你的答案**：`prompt`、`user` 返回原对象；`call`、`content` 不是同一个对象（类型说不上来）。

**✅**** 判断全对。** 补上类型名：

| 步骤 | 返回类型 |
| --- | --- |
| `.prompt()` | `ChatClientRequestSpec` |
| `.user(q)` | `ChatClientRequestSpec`（**还是它**） |
| `.call()` | `**CallResponseSpec**` ← 从这换对象 |
| `.content()` | `**String**` ← 连对象都不是了 |


**规律**：中间步骤返回"**下一步能用的接口**"，最后一步返回"**真正的值**"。

### 3.2 实现类 / Builder 的关系
**你的答案**：实现类好像叫 D 或 B；Builder 是 ChatClient 的嵌套接口；实现类"有这个接口但不强要求实现"。

**补清楚**：

+ `ChatClient` 的实现类 = `**DefaultChatClient**`
+ `ChatClient.Builder` 的实现类 = `**DefaultChatClientBuilder**`
+ **它们是两个独立接口**：`Builder` 只是"写在了 `ChatClient` 内部"（嵌套），**不代表 **`**ChatClient**`** 的实现类必须实现它**

```plain
public interface ChatClient {                 // 接口 A
    interface Builder { ChatClient build(); }  // 接口 B（嵌套，但独立）
}
public class DefaultChatClient implements ChatClient { ... }              // 只实现 A
public class DefaultChatClientBuilder implements ChatClient.Builder { ... } // 只实现 B
```

### 3.3 为什么要给 Builder
**你的答案**：框架只给了 builder 的 bean；build 方便更灵活地注入（说不上怎么灵活）。

**✅**** 核心对了。** 补"怎么个灵活法"：

`Builder` 上有一堆 `defaultXxx()` 方法（我解字节码看到的）：

```plain
builder.defaultSystem("你是一个简洁的助手")   // 预设人设
       .defaultOptions(...)                   // 预设参数（温度、maxTokens）
       .defaultAdvisors(...)                  // 预设拦截器（记忆、日志）
       .build();
```

**如果框架直接给你成品 **`**ChatClient**`**，这些就没法在构造时设置了。**

## Q4 异常分层
### 4.1 为什么不能用 BusinessException
**你的答案**：AI 服务不是业务逻辑，算系统异常，但 JVM 抛不了。

**✅**** 结论对。** 措辞补一处：它是"**外部依赖/配置**的问题"，不是"我们项目内部的 bug"（内部 bug 也是系统异常，但成因不同）。

### 4.2 ⚠️ 语义说反了
**你的答案**：`NonTransient` 是"尝试多次的"，对应 Key 错。

**❌**** 恰恰相反**：`NonTransient` = **Non（不）+ Transient（短暂的）** = "**不是暂时性问题，重试也没用**"。

**证据就在我们的实测里**：Key 错那次，**0.5 秒就返回了**（因为它知道重试没意义）；而网络那一次，**跑了 2.8 秒、重试了 3 次**。

**一句话判据（背这句）**：

**对方说话了（回了 4xx）→ **`**NonTransientAiException**`（Key 错 / 额度不足 / 参数错） **对方没说话（连不上、等不到）→ **`**ResourceAccessException**`（网络 / 超时）

### 4.3 谁抛的
**你的答案**：不是 JVM，是 Spring AI 抛的。

**✅**** 对。** 精确一点：

+ `NonTransientAiException` → **Spring AI 的代码**（它拿到 401，先"看懂"，再 new 一个异常 throw）
+ `ResourceAccessException` → **Spring 的 HTTP 客户端**（包住了底层的 `ConnectException`）

**JVM 只抛程序级错误**（NPE、数组越界、除零）。**这两类都是"别人代码里 throw 出来的事实"。**

## Q9 日志
### 9.1 ⚠️ 把两件独立的事混成了一件
**你的答案**：`{}` 是占位符；用 `+` 拼接就没有那堆 `at`；我猜 log 内部处理了 `e` 才让我们看到 `at`。

**前半对，后半混了。** 这是**两个完全独立的机制**：

| 机制 | 解决什么 |
| --- | --- |
| `**{}**`** 占位符** | **性能**：只在真要输出时才格式化（`+` 会无条件拼接，产生垃圾字符串） |
| **传 **`**e**`**（异常对象）** | **堆栈**：SLF4J 发现最后一个参数是 `Throwable`，就自动打印整条堆栈 |


**"有 **`**at**`**"跟 **`**{}**`** 一点关系都没有** —— 它取决于**你有没有把异常对象传进去**：

```plain
log.error("失败", e)                // ✅ 有堆栈
log.error("失败", e.getMessage())   // ❌ 没堆栈（因为传的是字符串）
log.error("失败: " + e)             // ❌ 也没堆栈（拼成字符串了）
```

### 9.2 `Result` 里为什么 `{}` 不生效
**你的答案**：应该不会吧，他只能换后面那个形参。

**结论对，机制要准确**：`**{}**`** 的"解释权"在接收它的方法手里**。

+ SLF4J 内部写了"解析 `{}` 并填参数"的代码 ✅
+ `Result.error(code, msg)` 只是把 `msg`**存起来**，**没有任何解析代码** ❌
+ 序列化成 JSON 时，**只抄字符串，不做替换**

### 9.3 ✅ 对（前者有完整堆栈）

## ★ 附加：RAG
**你的答案**：不是让它看到；我提的是"提供受限方法给 DeepSeek 用"；RAG 是分割内容 → 按某种方式存储 → 让 AI 根据内容回答。

**你提的"受限方法" = Tool Calling**（白名单选择，模型不碰数据库）✅ 这个理解是对的。

**RAG 你说了 2/3，漏了最关键的一环：检索。**

完整流程四步：

```plain
① 切分     把你的文档/数据切成小段（chunk）
② 向量化   每段变成一串数字（Embedding），存进向量库
③ 检索     用户提问 → 也变成向量 → 找出"最相关的几段"   ← 你漏了这步
④ 生成     把"那几段 + 用户问题"拼进提示词 → 模型基于它们回答
```

**没有第 ③ 步，就变成"把所有内容塞给模型"** —— 那既塞不下，也贵得离谱。

**一句话概括 RAG（判据就在这句话里）**：

**不是让模型去查库，而是"你查出来，喂给它读"。** 模型始终只做一件事：**基于你给的材料回答**。
