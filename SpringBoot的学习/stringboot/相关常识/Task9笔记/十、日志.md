### 1 `{}` 是什么
**日志框架的占位符**（不是形参）：

```plain
log.warn("缺少必需参数: {}", e.getParameterName());
//       └─ 参数1：字符串 ─┘  └─ 参数2：值 ─┘
```

**依然传两个参数**，替换发生在**方法内部**（SLF4J 自己解析）。

**为什么用 **`**{}**`** 不用 **`**+**`：`{}` 是**惰性格式化** —— 只在真要输出时才拼；`+` 会**无条件拼接**，产生大量垃圾字符串。

### 2 为什么 `Result.error` 里写 `{}` 不生效
`**{}**`** 的"解释权"在接收它的方法手里**：

+ SLF4J 内部**实现了**解析逻辑 ✅
+ `Result.error(code, msg)`**只是存值**，没有任何解析代码 ❌
+ 序列化成 JSON 时**只抄字符串** → 前端看到 `{}` 两个字符

### 3 三样东西的区别
| 写法 | 输出 |
| --- | --- |
| `log.error("msg", e)` | **完整堆栈**（异常类 + message + 所有 `at ...` + `Caused by`） |
| `log.error("msg", e.getMessage())` | 只有那一句话（**无堆栈**） |
| `log.error("msg: " + e)` | 同上（拼成字符串了，**堆栈丢失**）← **反模式** |
| `e.toString()` | 类名 + ": " + message（**一行，无堆栈**） |


**结论**：

+ 排查问题**必须**`log.error("msg", e)`（要堆栈才知道"在哪炸的"）
+ `e.toString()` 是它的**降级版**（有类型、没堆栈），**实际开发中几乎不用** —— 因为有你就不用降级版

### 4 日志级别怎么选
**判据：谁该被叫醒？**

| 情况 | 级别 | 理由 |
| --- | --- | --- |
| 用户输入问题（空 q、缺参数） | **WARN** | 预期内、高频、我们自己处理得了 |
| 业务失败（重名、不存在） | **WARN** | 同上 |
| 配置/账户问题（Key 错、额度不足） | **ERROR** | 我们自己搞错了，**要人看** |
| 未预料的异常（兜底） | **ERROR** | 可能是 bug，**必须有人查** |


**"发生很多次"恰恰是 WARN 的理由**，不是 ERROR —— 否则日志天天一片红，真正的故障被淹没（**告警疲劳**）。
