### 1 三类真实异常（实测）
| 场景 | 异常类型 | 是否重试 | 日志级别 | 返回 code |
| --- | --- | --- | --- | --- |
| Key 错 / 额度不足 | `org.springframework.ai.retry.NonTransientAiException` | ❌ 不重试（0.5s 返回） | **ERROR** | 503 |
| 网络不通 / 超时 | `org.springframework.web.client.ResourceAccessException` | ✅ 会重试（2.8s） | **WARN** | 503 |
| 缺参数 `q` | `MissingServletRequestParameterException` | — | **WARN** | 400 |
| 空字符串 / 纯空格 | 我们自己的 `BusinessException` | — | **WARN** | 400 |


### 2 一句话判据（背这句）
**对方说话了（回了 4xx）→ **`**NonTransientAiException**`**对方没说话（连不上、等不到）→ **`**ResourceAccessException**`

拆词记忆：

+ **Non**（不）+ **Transient**（短暂的）= "**不是暂时性问题，重试也没用**"
+ **Resource**（资源）+ **Access**（访问）= "**连资源都摸不到**"

### 3 ⚠️ 谁抛的？不是 JVM
**JVM 只抛程序级错误**（NPE、数组越界、除零）。

这两个是**框架代码抛的**：

```plain
① DeepSeek 服务器返回 HTTP 401 + JSON 错误体
        ↓
② Spring AI 的 DeepSeekApi 看到 401（非 2xx）→ 判定"客户端错误、重试无意义"
        ↓
③ 自己 new NonTransientAiException 抛出来
        ↓
④ 冒泡到我们的 handler
```

**JVM 全程不知道发生了什么** —— 它只管执行字节码，不懂 HTTP。

### 4 为什么 AI 不可用不能用 BusinessException
Task8 定的判据：**业务异常 = 用户能理解和应对**。

+ 重名了 → 改个名就行 ✅ 业务异常
+ **AI 服务挂了 → 用户无能为力** ❌ → 系统异常

### 5 为什么不能把 `e.getMessage()` 返给前端
**实测它里面有什么**：

| 异常 | message 内容 |
| --- | --- |
| `NonTransientAiException`（401） | `Authentication Fails, Your api key: ****test is invalid (request_id: ea43...)` ← **Key 后四位 + 内部 ID** |
| `ResourceAccessException` | `I/O error on POST request for "http://127.0.0.1:9/chat/completions"` ← **内网地址 / 接口路径** |


**规则**：

+ **业务异常**（我们自己 throw 的）→ message 可以返前端（安全）
+ **系统异常**（框架/库抛的）→ **只进日志**，前端给泛化文案

### 6 ⚠️ "URL 路径" ≠ "磁盘路径"
+ **URL 的 path**：`/chat/completions`（网络地址的一段）
+ **磁盘路径**：`C:\Users\ASUS\IdeaProjects\demo`（文件位置）

**内网地址泄露的危害**：暴露攻击面（有哪些接口、在哪台机器、什么端口）→ 为后续攻击指路 / 可能配合 SSRF。
