**不管有没有 advice，抛异常的都是 **`**@Valid**`**，区别只在"谁接"。**

| 情况 | 谁接 | 结果 |
| --- | --- | --- |
| 现在（没写 advice） | Spring 内置的 `DefaultHandlerExceptionResolver` | 400 + "Bad Request" + 默认错误页 |
| Task6 之后 | 我们的 `@RestControllerAdvice` | 我们的 `Result`，message 到达前端 |


推导顺序（**异常是因，状态码是果**）：

```plain
捕获到 MethodArgumentNotValidException
   ↓  Spring 判定：这类异常 → HTTP 400
   ↓  再问协议：400 的固定短语是什么？ → "Bad Request"
   ↓  拼成响应发出去
```

`@RestControllerAdvice` 之所以能接管，是**因为它的优先级高于内置处理器**（`@ControllerAdvice` 排在 `DefaultHandlerExceptionResolver` 前面）。

**一旦我们接住，内置兜底根本不会执行** —— 不是"我们捞出来再交给 Spring 打包"，而是**抢活**。
