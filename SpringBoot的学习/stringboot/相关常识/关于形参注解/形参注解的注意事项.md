## delete 用 path 更行业惯例
资源"是哪个"用路径标识（`/user/delete/4`），这是 REST 惯例；用 `?id=4` 也能跑，但偏"不地道"。

## 把 int 当布尔值用 —— 完全可以，而且标准
`mapper` 返回的 `int` 是"受影响行数"，你写 `if (result > 0)` 本质就是把它当"成功/失败"的布尔判断。**这正是业界最常用、最实用的写法**

****

## 形参注解混用也完全正常，比如改接口常写成：
```java
@PutMapping("/update/{id}")
public String update(@PathVariable Long id, @RequestBody User user) {
    user.setId(id);          // id 来自路径
    userMapper.updateById(user); // 其它字段来自请求体
}

```

**路径 id 是"权威"，body 里的 id 我们不认，强制用路径的 id 覆盖**。这就是防止客户端乱写 id。

更精确一点：不是"body 默认没有 id"，而是**就算客户端在 JSON 里写了 **`**id:99**`**，我们也不信它，用 **`**setId(路径的4)**`** 盖掉**。两种情况（body 有 id / body 没 id）都靠这行 `setId` 解决——要么补上，要么覆盖。所以"画蛇添足"其实是"故意保险"。
