## <font style="color:rgba(0, 0, 0, 0.9);">delete 用 path 更行业惯例</font>
<font style="color:rgba(0, 0, 0, 0.9);">资源"是哪个"用路径标识（</font>`<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">/user/delete/4</font>`<font style="color:rgba(0, 0, 0, 0.9);">），这是 REST 惯例；用 </font>`<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">?id=4</font>`<font style="color:rgba(0, 0, 0, 0.9);"> 也能跑，但偏"不地道"。</font>

## <font style="color:rgba(0, 0, 0, 0.9);"></font><font style="color:rgba(0, 0, 0, 0.9);">把 int 当布尔值用 —— 完全可以，而且标准</font>
`<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">mapper</font>`<font style="color:rgba(0, 0, 0, 0.9);"> 返回的 </font>`<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">int</font>`<font style="color:rgba(0, 0, 0, 0.9);"> 是"受影响行数"，你写 </font>`<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">if (result > 0)</font>`<font style="color:rgba(0, 0, 0, 0.9);"> 本质就是把它当"成功/失败"的布尔判断。</font>**<font style="color:rgba(0, 0, 0, 0.9);">这正是业界最常用、最实用的写法</font>**

## <font style="color:rgba(0, 0, 0, 0.9);">形参注解混用也完全正常，比如改接口常写成：</font>
```java
@PutMapping("/update/{id}")
public String update(@PathVariable Long id, @RequestBody User user) {
    user.setId(id);          // id 来自路径
    userMapper.updateById(user); // 其它字段来自请求体
}

```

**<font style="color:rgba(0, 0, 0, 0.9);">路径 id 是"权威"，body 里的 id 我们不认，强制用路径的 id 覆盖</font>**<font style="color:rgba(0, 0, 0, 0.9);">。这就是防止客户端乱写 id。</font>

<font style="color:rgba(0, 0, 0, 0.9);">更精确一点：不是"body 默认没有 id"，而是</font>**<font style="color:rgba(0, 0, 0, 0.9);">就算客户端在 JSON 里写了 </font>**`**<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">id:99</font>**`**<font style="color:rgba(0, 0, 0, 0.9);">，我们也不信它，用 </font>**`**<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">setId(路径的4)</font>**`**<font style="color:rgba(0, 0, 0, 0.9);"> 盖掉</font>**<font style="color:rgba(0, 0, 0, 0.9);">。两种情况（body 有 id / body 没 id）都靠这行 </font>`<font style="color:rgba(0, 0, 0, 0.9);background-color:rgba(0, 0, 0, 0.05);">setId</font>`<font style="color:rgba(0, 0, 0, 0.9);"> 解决——要么补上，要么覆盖。所以"画蛇添足"其实是"故意保险"。</font>
