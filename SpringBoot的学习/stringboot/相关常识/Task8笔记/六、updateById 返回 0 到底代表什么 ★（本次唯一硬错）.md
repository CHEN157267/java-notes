### ① 是「匹配行数」，不是「影响行数」
〔实测：JDBC 探针〕

```plain
id=1 把值从 'a' 改成 'a'（完全没变） => 返回 1
id=1 把值从 'a' 改成 'c'（变了）     => 返回 1
id=999（id 不存在）                  => 返回 0
```

→ **"值完全没变"还返回 1** ⇒ 它数的不是"真正改了几行"，而是"**匹配到几行**"（found rows）。

### ② 为什么"值没变"问题会存在
前提是 MySQL 连接参数 `**useAffectedRows=false**`（Connector/J 默认值）。

+ `false`：返回**匹配行数**（值没变也返回 1）；
+ 若哪天 URL 加了 `useAffectedRows=true`：语义翻成"**影响行数**"，"值没变"会返回 **0** → 那个 404 判断就会**误报**。

### ③ 结论
+ 返回值**恰好只有 {0, 1}**（id 是主键，最多命中 1 行，不可能返回 2+）。
+ **0 ⟺ 该 id 不存在**（严格补：也包括"执行那一刻这行被并发删了"）。
+ 0 **不是**"值没变"，也**不是**"系统出错"（系统问题会**抛异常**，不会返回 0）。

### ④ 为什么末尾那句 `!= 0` 不是废话：防并发（TOCTOU）
"**检查—使用**"之间存在竞态窗口：

```plain
请求 A: exists(id=5) 通过 ✅
                          ← 就在这两步之间 ↓
请求 B: DELETE id=5（把 5 号用户删了）
请求 A: updateById(id=5) → 匹配 0 行 → 返回 0
```

没有末尾那句，请求 A 会**以为成功了**（其实什么都没改）—— **静默谎报成功**。末尾那句就是**以执行结果为准，兜住这个窗口**。

学名 **TOCTOU**（Time-Of-Use / Time-Of-Check）。它是**安全网**，不是主逻辑；正常顺序流程走不到。

### ⚠️ 本次自测踩的坑
答成了"**影响行数**"，而且理由（"因为前面 exists 判过了"）跟返回什么数字**毫无关系**。 **结论对、名字错 → 判半对**。"匹配行数"这个词必须换过来，它才是"为什么 0 ⟺ 不存在"的钥匙。
