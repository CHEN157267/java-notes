| | 返回状态码 | 抛异常 |
| --- | --- | --- |
| 它是什么 | 一个**值**（普通数据） | 一次**控制流跳转** |
| 能不能被忽略 | **能**（编译器不管你有没有看它） | **不能**（当前方法立刻中断，必须有人接） |
| 犯错的样子 | **静默谎报成功**：没人检查 → 程序照常往下跑 | 想忽略也忽略不掉，会一路冒泡到 advice |
| 开销 | 极低 | 较高（要构造对象 + 填调用栈） |
| 适合 | 高频、**预料内**的多种分支；跨进程/接口（RPC、第三方 API） | 异常情况；真实项目的默认风格 |


+ 返回码**最大风险 = 调用方忘了检查**（`updateUser` 返回 `-1`，Controller 直接 `Result.success(...)` 就静默成功）；
+ 换上异常后风险**为什么消失 = 异常夺走控制权**，不是"能不能忽略"，是"**根本没法忽略**"。

一个是"我告诉你结果，你自己看着办"；一个是"我出事了，你必须接住我"。
