1. `**@Component**`** 那一族 → 告诉 Spring"这里要生成一个 bean"** ✅
    - `@Service` / `@Controller` / `@Repository` 都是 `@Component` 的**派生注解**（写在 `@Component` 上面，等于"换了个更具体的名字"）。"类似父类"的比喻**方向对**，只是它们**不是**继承关系，叫**"派生/组合"**。
    - 功能上没差别，都是让 Spring 扫描到、创建 bean。
2. `**@Mapper**`** 那一族 → 告诉 MyBatis 搞个实现类 + 对象，交给 Spring 存进池子** ✅ 
    - ：`@Mapper` 是 **MyBatis 的**注解，由 MyBatis 的扫描器处理（`@MapperScan` 或 `@Mapper`），不归 Spring 的 `@Component` 扫描管线管。但**结果一样**——最后往 Spring 容器里注册了一个 bean。所以给 Spring 当 bean 用没错。
3. `**@Autowired**`** → 告诉 Spring"我需要符合这个条件的 bean，发一个过来"** ✅
    - 补一个关键点：这里说的"**条件**"，默认是**按类型（by type）匹配**——找容器里类型对得上的 bean。**这正是"多个实现会冲突"的原因**：两个 `UserService` 实现，类型都匹配，Spring 不知道选哪个，就报 `NoUniqueBeanDefinitionException`。你前面学的 **@Primary / @Qualifier**，就是用来补充这个"条件"的。



关于**@Primary / @Qualifier**

| **注解** | **贴哪** | **作用** | **比喻** |
| --- | --- | --- | --- |
| `@Primary` | 贴**实现类** | 宣布"我是默认首选" | 给常用那个盖个"默认"章 |
| `@Qualifier("名字")` | 贴**注入处** | 当场点名"我就要这个" | 领料单上写清具体型号 |


```java
// 两个实现
@Service @Primary                                   // ← 默认选它
public class UserServiceImpl implements UserService { ... }

@Service
public class UserServiceImplCache implements UserService { ... }   // 备用

// 注入处
@Autowired
private UserService userService;                    // 没点名 → 拿 @Primary 那个

@Autowired @Qualifier("userServiceImplCache")       // ← 点名要缓存版
private UserService cacheService;

```

两个要点：

1. **优先级**：`@Qualifier` **比** `@Primary` 更具体——你当场点名了，就按点名的来；没点名，才回落到 `@Primary`。
2. `**@Qualifier**`** 里的名字**：默认是**类名首字母小写**（`UserServiceImplCache` → `"userServiceImplCache"`）。除非你在 `@Service("xxx")` 里自己起了名。

| **bean 从哪来** | **谁加工** | **注解** |
| --- | --- | --- |
| 你自己写的类 | Spring 扫描 | `@Component`<br/> 家族（含 `@Service`<br/>） |
| 接口（如 Mapper） | MyBatis 代加工 | `@Mapper` |
| 写个方法手工造 | Spring 调你的方法 | `@Bean`<br/>（放在 `@Configuration`<br/> 类里） |
